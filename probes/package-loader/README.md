# Record 0057 gate 1: real loader and graph core

Implementation tests are in rnx, not an archived copy. The source-map handoff,
manifest parser, fingerprinting and commands remain later gates. No binary can
load a package map from the CLI at this checkpoint.

Run from the rnx checkout, sequentially (feature builds share the target directory):

```sh
TERM=xterm cargo test --locked -- --test-threads=1
TERM=xterm cargo test --locked --features test-support -- --test-threads=1
TERM=xterm cargo test --locked --features test-support,server-runtime,project-sources -- --test-threads=1
cargo test --locked --manifest-path tools/project/Cargo.toml
cargo clippy --locked --manifest-path tools/project/Cargo.toml --all-targets -- -D warnings
cargo fmt --check
cargo fmt --check --manifest-path tools/project/Cargo.toml
```

The root's feature test uses `program::Loader` and its real entry/file/read path.
The graph tests give the private tool core parsed nodes through a callback;
manifest bytes and the CLI do not enter those tests. Both sides meet at the
specified expanded (logical prefix, physical root) representation. End-to-end
parsing/serialization and CLI integration are explicitly not passed here.

Fixture directories are generated by each test and removed on drop. Prefix
selection, read allowance and source identity are production loader code. Only
the constructor used to inject mounts remains internally unused outside tests
until the CLI handoff lands. The graph core similarly has an explicit staged
unused-code allowance. Neither is a new supported public rnx API.

Results: `results/package-loader-0057/`. No latency, throughput or startup claim;
record 0057 gate 6 owns matched performance measurement.
