# Bare rustc and 42

The user requested data for the claim that bare rustc often compiles faster
than a terminal refresh. This probe changes no rnx or application code.

```
python3 probes/rustc-42/run.py results/rustc-42-new --native
python3 probes/rustc-42/analyse.py results/rustc-42-new
```

Use a new output directory: the driver refuses to overwrite retained results.
It uses the locally installed stable and (only for untimed attribution) nightly
compilers, no installation or network. `target/` executables are ignored.
A retained ordinary rnx binary from closed 0167 is required at
`probes/fmt-0167/target/stock`; its hash is checked in the conditions record.

Three programs, eight full-build configurations; six metadata/object paths;
eight compile-and-run printing cases; prebuilt execution, tool overhead and
contemporaneous interpreters. Five warmups, 90 samples/config across three
seeded shuffled rounds on CPU4 when allowed. Unpinned and four-core controls
repeat the descriptively fastest full build, with 90 samples each. Read the
phase labels before comparing results. All executable outputs/statuses are
checked; the exit42 diagnostic intentionally returns42. Compilers have a
30-second per-invocation timeout. There is no Cargo, LTO or incremental cache.
Compilation is fresh, with a warm OS page cache. The same shell-free Python
clock measures all invocations; this is a controlled counterpart to the older
hyperfine -N leaderboard, not a claim its historical numbers are current.

`conditions.json` retains exact commands, sources, binary hashes, versions,
linker comments, affinity and frequency policy. `samples.jsonl` retains every
measured duration. `summary.json` has aggregate and per-round statistics;
`summary.md` leads with the frame-budget fraction table. The analysis refuses
missing/duplicate samples or an inconsistent selected affinity-control case.

Protocol reviewed by Claude before the deciding run. Source-to-answer prints42
throughout; compiler-stage, empty/exit and cached-binary results are diagnostic.
The thread's separate LTO/interpreter-build remark is not tested here.

## Deciding clock and retained failed attempts

The original Python timeout clock adds polling delay to short commands. It is
retained at results/rustc-42/ (polling-summary.*). A blocking-Python replay is
retained at blocking-final/; it failed the pre-agreed clock sanity check and
is not the deciding data. Native-final/ is the deciding run, promoted to the
root summary.md. Inputs, variants, seeds, counts and selection never changed.
No samples were removed and no overhead was subtracted. The independent
hyperfine check is retained at the root; its source is hyperfine_check.py.

The dependency-free native clock prepares Command objects before its Instant
interval and serializes statuses and captured output after it. Child spawn,
pipe capture and blocking waits are inside the clock. Every runtime uses it.
Python orchestration/launch costs are outside. Build and preflight it first:

```
rustc --edition=2024 -O probes/rustc-42/clock.rs -o probes/rustc-42/target/clock
python3 probes/rustc-42/preflight.py /tmp/new-clock-preflight.json
timeout --kill-after=5s 600s python3 probes/rustc-42/run.py results/rustc-42-new --native
python3 probes/rustc-42/analyse.py results/rustc-42-new
```

Preflight requires an already-built target/warm-print-default (generated by
run.py's setup, or compile print.rs to that path with default rustc flags).
It requires 50-sample medians for /bin/true and cached Rust to match independent
hyperfine references 0.240 and 0.353 ms within ±0.150 ms, else STOP. The deciding
run also passed those bounds (0.349 and 0.440 ms). Preflight passed before it
started (0.317 and 0.381 ms). All datasets remain labeled; nothing is overwritten.
Clock/helper sources and binary SHA-256s are recorded in final conditions.
The mode field blocking_wait refers to Python orchestration; native_clock=true
identifies the native blocking-wait measured interval. Nightly phase totals
are not a stable decomposition and strace is untimed.
