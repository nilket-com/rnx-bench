Published rnx [bc0fada](https://github.com/nilket-com/rnx/commit/bc0fada750c6fa50f2b0e765a2985155bd933e00)
pins Rune [1b4b66bd](https://github.com/nilket-com/rune/commit/1b4b66bd3657868ecb1d49f8b3f355585b3ec98d).
The adapter uses Polars 0.55.2; the separate comparison uses Polars
[py-2.1.0](https://github.com/pola-rs/polars/commit/7f902bd3ffd27ff82d14278a09a295ff2f7aed92).
Measured on an Intel i7-14700 measurement host, CPU 2 affinity, with one Polars
thread and the measurement lease held. These are individual first/warm calls,
not repeated-sample means. No results are extrapolated from smaller inputs.

## Matched x + 1 comparison

All modes use identical, varied, non-null i64 inputs `(i % 1009) - 500`, with
every output checked and full-output checksums equal. The host path includes
output allocation and processing; input construction, preparation, validation,
Arrow wrapping and output destruction are outside this interval. Polars eager
assignment includes output allocation and destruction of the previous output.
The separate real CLI measurement below includes the Arrow adapter and thread
join, and uses constant inputs. It is not substituted into this matched table.

Rune checks integer overflow; the Polars comparator wraps. These chosen inputs
do not overflow. Host release defaults differ from the Polars comparator's
opt-level 3, one-codegen-unit, no-LTO recipe. This is a reported comparison, not
a same-build-recipe performance gate. The compiler is Rust 1.98.1 / LLVM 22.1.8;
recorded Rust flags are empty, with no `target-cpu=native`.

`Ir` means executed machine instructions measured separately under Callgrind.
Wall time and user cycles come only from direct runs with stable thermal counters
and PMU enabled time equal to running time. Profiled wall time and cycles are
excluded, including the thermally flagged 100M per-row reference profile.
Logical GB/s counts 8 bytes read plus 8 bytes written per row, in decimal GB;
it is not a measurement of physical DRAM traffic.

The user-cycle gap is larger than the wall-time gap. Output page faults also
consume kernel time, which user-cycle counters exclude; neither ratio alone
measures total CPU work. Kernel-cycle attribution was not measured. The results
do not establish one instruction per element end to end or a general script
speedup. Polars first-call and preparation times were not measured here.

At 100M rows the host output capacity is 800,000,000 bytes; retained kernel
storage is 1,968 bytes. Warm AVX2 has eight malloc calls at both 10M and 100M,
9,766 / 97,657 SIMD block entries (ceil(rows/1024)), and no named scalar/VM entry.
The per-row reference has exactly 10M / 100M scalar call and Executor entries.
Polars warm output allocation has five allocations, zero reallocations and
800,000,248 requested bytes at 100M. See the archived
[allocation evidence](column-0205-2026-11-04/allocation.json).

## Actual script map boundary

The production `rnx-polars` binary runs the public handle:

```rust
let k = polars::column_kernel(
    "pub fn map(x) { x + 1 }", "map", ["i64"], "i64")?;
let output = k.map([input])?;
println!("{}", k.last_path());
```

The script runs with `--budget 1000000000`. The CLI default remains 2,000,000;
these large maps require an explicit allowance. The outer script uses the stock
VM; the prepared inner column computation uses the primitive path. Successful
rows are charged once; null rows do not execute the scalar operation or consume
its row charge. This does not add closure-taking `Series.map`.

Input construction, kernel preparation and complete output equality checks are
outside the measured map. Time brackets `k.map` at 1 ms resolution. GDB/vgdb
opens and closes the instruction interval at the typed map host-call boundary,
collecting all threads and witnessing the worker; it includes conversions,
output allocation, processing and join/return. First and warm calls both complete
with one attempt, zero replays and the expected full output.

Flat i64 `x+1` uses input 1; fused `x*2+y` uses 1 and 2; generic `x*3+y` uses
the same inputs; F64 uses 1.0 and 2.0; Boolean uses true. Sliced cases offset the
first input by 3 and the second by 5; the first input has a valid half followed
by a null half in separate chunks, while other inputs can have independent
boundaries. Costs below are per **logical row**, including nulls, not per valid
row. Null payloads are not evaluated. These generic-layout costs remain much
higher than the flat cases despite avoiding a whole-input copy.

## Publication evidence and limits

The final fresh acceptance chain passed, including cross verification, clean
inventory generation and ordinary host/adapter/CLI controls. Earlier successful
stages were reused only through the reviewed source/receipt/log-hash chain.
The measured CLI binary hash is recorded in [provenance.json](column-0205-2026-11-04/provenance.json).
The measurement source precedes the final tooling and test-only amendments.
Same-directory paired release builds prove identical `.text` and `.rodata` for
the test-only change; later changes are tooling only. Whole executable hashes
differ, and cross-host binary reproducibility is not claimed.

Existing-path raw performance status remains **FAIL**, with three explicitly
reviewed **ACCEPTED_ATTRIBUTED** groups: callback conversion adds 10 instructions
per row from inlining drift (about 0.1–0.13%); the payload accessor adds one
instruction per access from Rune-pin code generation (about 0.2% in the list
controls); two small fib/permute totals are allocator variation. Thresholds were
not rewritten. This publication is not an unqualified zero-regression result.

Inputs are borrowed; output buffers transfer into Arrow. Polars owner-metadata
allocations retain its existing infallible allocator behavior, separately from
the fallible bounded buffers. Strings, objects and arbitrary closures are not
SIMD column primitives. Unsupported functions retain a scalar path.

## Evidence and reproduction

[Compact summaries and hashes](column-0205-2026-11-04/MANIFEST.json) retain every
case, path witness, original capture/receipt/profile digest, allocation proof
and source identity. Raw logs, profiles and environment dumps are not committed;
their hashes bind the retained capture artifacts. This archive validates the
recorded evidence, not an independent rerun of those private artifacts.

[Measured harness sources and locked recipes](../probes/column-0205/README.md)
are archived with private machine paths replaced by documented placeholders.
The Polars Rust files have a verified indentation-only conversion to tabs;
original measured hashes and the reversible whitespace proof are retained.
The existing whole-process N6 matrix is unchanged and still describes its older
named binary. To validate the archive and regenerate only these tables:

```sh
python3 -B scripts/render_column_0205.py
python3 -B scripts/render_column_0205.py --check
python3 -B -m unittest discover -s scripts -p test_column_0205.py
```

The renderer never starts a measurement. It rejects changed archived files,
missing/duplicate cases, wrong paths, missing worker/entry witnesses, mismatched
checksums and invalid headline timing. New captures require their own output
checks, build identities, lease, thermal/PMU validity and review.
